# 插件范围与阶段规划

> 记录时间：2026-11-18
> 前置阅读：[00-jni-android.md](00-jni-android.md)（原理与证据）

---

## 0. 目标与非目标

**目标**

1. 一套面向大鹏 DPVR 头显的 UE5 插件，蓝图拖节点就能用，不需要碰 C++/Java。
2. 能力覆盖对齐 PICO 企业插件那个量级（对方 243 个函数），按"能做的先做"推进。
3. 插件独立交付：放到任意 UE 5.5 工程的 `Plugins/` 下就能编、能打包。

**非目标**

| 不做 | 原因 |
|---|---|
| 支持 PICO | 只对接大鹏。PICO 插件只作写法参考，不进本工程 |
| 做"厂商接口 + 双后端"抽象 | 只有一家后端，虚接口是纯负担。等真要接第二家再抽 |
| 逐字复刻 PICO 的 243 个 | 上限 = 标准 Android 能做的 + 大鹏 SDK 实际给的，不是 243 |
| 依赖系统签名的骚操作 | 除非大鹏明确给权限，否则不做 |

---

## 1. PICO 那 243 个到底是什么

按函数名关键词统计（`PICO_EnterpriseFunctionLibrary.h`，去重后 243 个 `PE_` 函数）：

| 能力域 | 数量 | 标准 Android 能不能做 |
|---|---|---|
| 屏幕 / 按键 / 音量 / IPD | 39 | 一半（改按键行为、禁电源键不行） |
| 投屏 / Miracast | 18 | 不能，厂商私有 |
| 大空间 / 地图 / ArUco | 17 | 不能 |
| WIFI 配置 | 14 | 部分（Android 10+ 限制严，企业场景要系统权限） |
| 应用管控（拉起/杀死/保活/白名单） | 13 | 部分（拉起和杀后台能，保活/白名单要权限） |
| 手柄 | 11 | 不能 |
| 相机 / VST | 12 | 不能（native `.so`） |
| 系统设置（语言/国家/初始化向导） | 11 | 部分 |
| 设备信息 / 电量 | 6 | 能 |
| OTA 升级 | 5 | 部分（装包能，整机升级不能） |
| 其他（眼动、动捕、虚拟显示、全局对话框、定时开关机、系统时间、服务绑定） | 84 | 少数能 |
| **合计（去重）** | **243** | —— |

> 分类有交叉（手柄与设备信息有 13 个重叠项），数量按关键词匹配统计，用于估规模，不用于精确对账。

## 2. 三档拆分

```
一档  无权限、纯标准 Android            ≈ 70 个   现在就能做
二档  标准 Android + 系统权限            ≈ 60 个   看头显给不给权限
三档  必须厂商 SDK                       ≈ 110 个  等大鹏
```

**为什么二档也难**：亮度、WIFI、保活、按键重映射，Android 都有 API，但都要 `WRITE_SETTINGS` / `CHANGE_WIFI_STATE` / 系统签名。普通 APK 拿不到，PICO 是靠 `tobservice` 系统服务绕过去的。大鹏大概率同套路。

## 3. 架构

只支持大鹏，所以**不做接口抽象**，一个后端到底：

```
        蓝图 / UMG
             │
   ┌─────────┴──────────┬──────────────────┐
   ▼                    ▼                  ▼
UAndroidBridgeLibrary  UDPVRBridgeLibrary  UAndroidBridgeSubsystem
  ~130 个，纯 Android     ~110 个，大鹏       事件：屏幕亮灭、网络变化、SDK 就绪
  引擎自带 + 自己的 Java   他们的 .so
```

| 层 | 放哪 | 职责 | 不许干 |
|---|---|---|---|
| 蓝图库 | `Public/*Library.h` | UFUNCTION 门面，参数校验、平台分支 | 不拼 JNI 参数 |
| 后端 | `Private/FDPVRBackend.*` | `.so` 的加载、符号解析、调用、类型转换 | 不暴露给蓝图 |
| JNI 封装 | `Private/XRDeviceKitJni.*` | 类/方法 ID 集中缓存，签名集中管理 | 不写业务 |
| Java | `JavaLibs/` 或 XML 注入 | 只调 Android 框架 | 不处理 UE 类型 |

**注入进 `GameActivity` 的 Java 只放"必须拿 Activity"的方法**（拉起 App、注册广播）。纯查询一律走独立 Java 类，避免重蹈 PICO 那份 3700 行。

## 4. 阶段与验收

| 阶段 | 内容 | 验收标准 | 预估 |
|---|---|---|---|
| **P0** | 插件骨架 + 3 个 API：电量（引擎自带）、屏幕状态（Java 注入）、亮度（Java 注入） | 真机上三个节点返回正确值；APK 里能看到注入的 Java | 1 天 |
| **P1** | 一档 ≈70 个 | 抽 10 个真机验证；`.gitignore` 干净，仓库能直接克隆编译 | 1 周 |
| **P2** | 大鹏 SDK 对接（三档） | 能读手柄电量；`.so` 缺失时降级不崩 | 1~2 周（看 SDK） |
| **P3** | 二档 ≈60 个 | 按实际拿到的权限逐条打勾 | 1~2 周 |

> 进度：P0 代码已完成（Win64 编译通过、XML 校验通过），安卓打包与真机验证待做。详见 [02-p0-library-skeleton.md](02-p0-library-skeleton.md)。

**P0 是唯一的验证关口**：XML 注入通不通、JNI 调不调得到、打包流程对不对，这三件事不通，后面全是空中楼阁。

## 5. 待大鹏确认（决定 P2 能不能开工）

1. SDK 是 **`.so` + 头文件**，还是 **`aar`/`jar`**？
2. 有没有 **C++ 接口**（不是 Java 封装）？
3. 哪些能力**需要系统权限或系统签名**？给不给？
4. 支持哪些 **Android 版本 / ABI**（arm64 必需）？

**拿到包先做的事**：解压 → 看目录。有 `jni/` 或 `libs/arm64-v8a/` 就是带 `.so` 的；只有 `classes.jar` 就是纯 Java。

## 6. 命名与仓库

| 项 | 值 | 理由 |
|---|---|---|
| UE 工程 | `XRDeviceKitDemo` | 工程只是开发/验证壳 |
| 插件 | `XRDeviceKit` | 不带厂商名，换后端不用改名 |
| 主模块 | `XRDeviceKitDemo` | 必须与工程同名 |
| 插件模块 | `XRDeviceKit` | 不能与工程模块重名，否则 UBT 报错 |
| GitHub 仓库 | `XRDeviceKit` | 交付物是插件，仓库名跟插件走 |

`uplugin` 里 `Description` 用英文，避免插件浏览器里中文编码乱码；中文描述放 README。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 大鹏 SDK 能力远少于 PICO | 三档做不满，总数缩水 | 先对表，别承诺数量 |
| 系统权限拿不到 | 二档大量功能做不了 | 提前问清楚，做不了的就标"不支持"，别硬做 |
| `.so` 依赖缺失 | 真机 `dlopen` 失败 | 用 `readelf -d` 查依赖，一起打进 APK |
| `GameActivity` 注入膨胀 | 和 PICO 一样变 350KB 烂摊子 | 只注入必须拿 Activity 的方法 |
| 工程与插件耦合 | 插件无法独立交付 | 定期在干净工程里只放 `Plugins/XRDeviceKit` 验证一次 |
