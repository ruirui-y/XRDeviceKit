# P1 第一批：设备信息与系统能力（28 个节点）

> 日期：2026-11-18
> 前置：[02-P0-插件骨架与三个设备API.md](02-P0-插件骨架与三个设备API.md)

---

## 1. 这一阶段要做什么

P1 的目标是"一档"：**不需要系统权限、能直接用标准 Android 或引擎接口拿到**的能力。

第一批只挑**引擎已经封装好**的那部分，不写一行 Java。目的有两个：

1. 用最低风险把节点数量从 3 个推到 28 个，验证蓝图库能否撑住规模；
2. 把"查引擎接口 → 包装 → 编译"这条流水线跑顺，后面接 Java 的部分就只剩「加一个文件」。

**不做**：需要 Java 的（屏幕事件、应用拉起、存储详情）、需要权限的、大鹏 SDK。

---

## 2. 怎么做的

### 2.1 沿用 P0 的分层，只往里加函数

```
蓝图
 └─ UXRDeviceKitLibrary        28 个 UFUNCTION，全部只转发
     └─ XRDeviceKit::Platform  28 个实现，唯一有 #if 的地方
         ├─ 引擎接口（本期全部走这条）
         └─ JNI（P0 的屏幕/亮度）
```

新增一个 **`Public/XRDeviceKitTypes.h`**：把引擎的 `EDeviceScreenOrientation`、`ENetworkConnectionType` 镜像成 `UENUM`。原因是这两个引擎枚举**不是 UENUM**，蓝图里根本看不到。

### 2.2 本期 28 个节点

| 分类 | 节点 | 底层 |
|---|---|---|
| Device | `GetBatteryLevel`、`IsCharging`、`IsLowPowerMode`、`GetBatteryTemperature` | `FAndroidMisc::GetBatteryState` 等 |
| Device | `GetCPUTemperature`、`GetCPUBrand`、`GetCoreCount` | `FPlatformMisc` |
| Device | `GetDeviceId`、`GetOSVersionString`、`GetAndroidMajorVersion`、`GetDefaultLocale` | `FPlatformMisc` |
| Device | `GetDiskFreeMegabytes`、`GetDiskTotalMegabytes` | `GetDiskTotalAndFreeSpace` |
| Display | `IsScreenOn`、`GetBrightness`、`SetBrightness` | JNI（P0 已有） |
| Display | `GetScreenOrientation`、`SetScreenOrientation` | `FPlatformMisc::Get/SetDeviceOrientation` |
| Network | `GetNetworkType`、`HasWiFiConnection` | `FPlatformMisc` |
| Audio | `GetDeviceVolume`、`IsHeadphonesPluggedIn` | `FPlatformMisc` |
| System | `CopyToClipboard`、`PasteFromClipboard` | `FPlatformApplicationMisc` |
| System | `GetProjectVersion`、`ShareURL` | `FApp` / `FPlatformMisc::ShareURL` |
| Haptics | `StartHaptics`、`StopHaptics` | `PrepareMobileHaptics` / `TriggerMobileHaptics` |

### 2.3 两个设计决定

| 决策 | 选的 | 没选的 | 理由 |
|---|---|---|---|
| 枚举怎么给蓝图 | 自定义 `UENUM`，平台层用 `switch` 显式映射 | `static_cast` 靠枚举顺序对齐 | 引擎改枚举顺序就静默错位，switch 至少编译期报重复/缺分支 |
| 磁盘空间单位 | 返回 int64 MB | 返回字节 | 蓝图里 int64 能存，但 MB 直接可读，不用调用方再除 |

## 3. 写完为什么不是理想效果

编译过了，**链接挂了**，两条一模一样的错：

```
XRDeviceKitPlatform.cpp.obj : error LNK2019: 无法解析的外部符号
"__declspec(dllimport) public: static void __cdecl FWindowsPlatformApplicationMisc::ClipboardCopy(wchar_t const *)"
(__imp_?ClipboardCopy@FWindowsPlatformApplicationMisc@@SAXPEB_W@Z)，
函数 "void __cdecl XRDeviceKit::Platform::CopyToClipboard(class FString const &)" 中引用了该符号
```

`ClipboardPaste` 同样报错，最后：

```
UnrealEditor-XRDeviceKit.dll : fatal error LNK1120: 2 个无法解析的外部命令
```

**注意这是链接错误不是编译错误**：头文件找得到（`HAL/PlatformApplicationMisc.h` 能包含），但符号在 `ApplicationCore` 模块里，模块没链接进来。

---

## 4. 怎么定位的

1. 看报错里的符号名 `FWindowsPlatformApplicationMisc::ClipboardCopy` —— 属于 ApplicationCore。
2. 回去看 `Build.cs`：`PrivateDependencyModuleNames.Add("ApplicationCore")` 被写在 `if (Target.Platform == UnrealTargetPlatform.Android)` 里面。
3. 也就是说**Win64 从来没有链接过 ApplicationCore**。P0 阶段没暴露，因为那时只用了 `FPlatformMisc`（Core 模块）。
4. 结论：依赖放错了作用域，不是代码问题。

---

## 5. 怎么解决的

把 `ApplicationCore` 从 Android 分支里提出来，变成全平台依赖：

```csharp
// 剪贴板在 ApplicationCore 里（HAL/PlatformApplicationMisc.h），全平台都要
PrivateDependencyModuleNames.Add("ApplicationCore");
```

改完重编：

```

[5/6] Link [x64] UnrealEditor-XRDeviceKit.dll
```
