# 资源统计与硬件信息

> 日期：2026-11-19
> 设备：DPVR P1Max（Android 12）
> 前置：[11-开发日志.md](11-开发日志.md)

---

## 1. 这一阶段要做什么

测试时想知道"游戏到底吃了多少资源"，需要三样东西：

1. **资源快照**：本进程 CPU、内存、线程数、帧时间、GPU 时间，一个结构体一次拿全
2. **硬件信息**：厂商型号、CPU、GPU、内存、屏幕、系统版本，单独节点（几乎不变）
3. **日志打印**：可配置间隔，每次采完自动打一行到 UE 日志，测性能时不用挂界面

---

## 2. 怎么做的

### 2.1 为什么必须后台采样

CPU 占用率不是某个瞬间的值，而是**两次采样的差值**：

```
t0：读 /proc/self/stat → utime0 + stime0
t1：读 /proc/self/stat → utime1 + stime1
占用率 = (utime1 + stime1 - utime0 - stime0) / 100 / (t1 - t0) * 100%
```

所以做成 `UXRDeviceKitStatsSubsystem`，用 `FTSTicker` 每 1 秒采一次，蓝图只读缓存。

### 2.2 数据来源

| 字段 | 来源 |
|---|---|
| 本进程 CPU | `/proc/self/stat` 的 utime+stime |
| 整机 CPU | `/proc/stat`，读不到退化到 `/proc/uptime` |
| 进程内存 / 峰值 | `/proc/self/status` 的 `VmRSS` / `VmHWM` |
| 线程数 | `/proc/self/status` 的 `Threads` |
| 整机可用内存 | 引擎 `FPlatformMemory::GetStats()` |
| 帧时间 / 线程耗时 / GPU | `GEngine->GameViewport->GetStatUnitData()`，没值就用 `GAverageFPS` 反推 |
| 电池 | 复用已有节点 |

### 2.3 日志格式

一行一个采样，前缀固定：

```
STATS|CPU=86.8% SYS=0.0% MEM=456MB PEAK=540MB ENG=457MB AVAIL=3456MB THREADS=69
      FPS=72.4 FRAME=13.8ms GT=0.0 RT=0.0 RHI=0.0 GPU=0.0ms GPUSE=0.00
      IO=0.0/0.0MB THERMAL=-1 BATT=-674mA 36.7C
```

间隔由 `StartResourceLogging(秒)` 指定，默认 1 秒。

## 3. 写完为什么不是理想效果

### 3.1 第一次跑直接段错误

```
Fatal signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x71c2490000
```

调用栈：

```
#00 memset
#01 FMallocPoisonProxy::Malloc
#02 FMemory::Malloc
#03 FFileHelper::LoadFileToString
#05 UXRDeviceKitStatsSubsystem::TakeSample
```

### 3.2 整机 CPU 永远是 0

诊断日志：

```
PROCDIAG|statLen=314 ticks=336 haveProc=1 statFileLen=0 total=0 idle=0 haveSys=0
```

`/proc/self/stat` 能读（314 字节），`/proc/stat` 读到 **0 字节**。

### 3.3 进程 CPU 也是 0，但 ticks 明明在涨

```
PROCDIAG|n=1 ticks=336 cpu=0.00
PROCDIAG|n=2 ticks=428 cpu=0.00     ← ticks 涨了 92，CPU 却还是 0
PROCDIAG|n=3 ticks=516 cpu=0.00
```

### 3.4 帧时间也是 0

`gv=1 unit=1`（GameViewport 和 StatUnitData 指针都拿到了），但 `frame=0.00`。

---

## 4. 怎么定位的

**3.1**：看栈就够了，问题在 `FFileHelper::LoadFileToString`。查它的实现：它按 `Ar.TotalSize()` 分配缓冲区，而 `/proc` 文件的 `stat` 大小是 0（有些是 -1），拿这个值去 `Malloc` 就会拿到垃圾长度、`memset` 时越界。

**3.2**：`statFileLen=0` 说明文件打不开——Android 12 上 `/proc/stat` 被 SELinux 限制，普通 App 读不到。同理 `/proc/uptime` 也读不到（`haveUptime=0`），所以兜底方案在本机也没生效。

**3.3**：这是我自己的逻辑 bug。原来的条件写成：

```cpp
if (bHasPrevious && bHaveProcess && bHaveSystem && Now > PrevSampleTime)
```

进程 CPU 和整机 CPU 被绑在一个条件里，整机数据读不到 → 整个块跳过 → 进程 CPU 永远是 0。**实际上进程 CPU 只需要 `/proc/self/stat`，和整机数据没关系。**

**3.4**：`FStatUnitData` 只有在引擎内部刷新统计时才写入（`UnrealEngine.cpp` 里那处），普通运行时字段一直是 0。指针非空不代表有值。

---

## 5. 怎么解决的

| 问题 | 改法 |
|---|---|
| `/proc` 读崩 | 不用 `FFileHelper`，改 `fopen` + 定长 `fread`（8192 字节），读完手动补 `\0` |
| 整机 CPU 读不到 | 加 `/proc/uptime` 兜底；本机两个都被挡，字段保持 0 并在文档里说明 |
| 进程 CPU 被连坐 | 拆开条件：进程 CPU 只看 `bHaveProcess`，整机 CPU 只看 `bHaveSystem` |
| 帧时间 0 | `FStatUnitData` 没值时用 `GAverageFPS` 反推（`1000 / fps`） |

### 字段可用性（P1Max 实测）

| 字段 | 状态 | 说明 |
|---|---|---|
| `CPU` | ✅ 86~90% | 单核跑满一个核的占用率，和 72 FPS 对得上 |
| `MEM` / `PEAK` / `ENG` / `AVAIL` | ✅ | 分别来自 /proc 和引擎内存统计 |
| `THREADS` | ✅ 69 | 和进程实际线程数一致 |
| `FPS` / `FRAME` | ✅ 72.4 / 13.8ms | 2D 面板 72Hz |
| `BATT` / 温度 | ✅ | 符号随厂商 |
| `SYS`（整机 CPU） | ❌ 0 | `/proc/stat` 与 `/proc/uptime` 都被 SELinux 挡住 |
| `GT` / `RT` / `RHI` | ❌ 0 | `FStatUnitData` 运行时不刷新 |
| `GPU` / `GPUSE` | ❌ 0 | 同上；Android 上本来也基本拿不到 |
| `IO` | ❌ 0 | `/proc/self/io` 同样受限 |
| `THERMAL` | ❌ -1 | 当前版本未接 |
