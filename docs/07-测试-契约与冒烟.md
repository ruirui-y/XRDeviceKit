## 1. 这一阶段要做什么

56 个节点、两个平台都编译通过，但**一条真机数据都没有**。这轮补三层验证，各自负责不同的问题：

| 层 | 文件 | 证明什么 | 谁跑 |
|---|---|---|---|
| 契约测试 | `Private/Tests/XRDeviceKitContractTest.cpp` | 节点没少、默认值对、调用不崩 | 命令行，10 秒 |
| 真机冒烟 | `Public/XRDeviceKitSmokeTest.h` + `Private/XRDeviceKitSmokeTest.cpp` | 真机上取值是否合理 | 设备 + adb |
| APK 检查 | `Tools/verify_apk.ps1` | 打包产物里符号齐不齐 | 打包后，2 秒 |

## 2. 怎么做的

### 2.1 契约测试

```cpp
IMPLEMENT_SIMPLE_AUTOMATION_TEST(FXRDeviceKitContractTest, "XRDeviceKit.ApiContract",
	EAutomationTestFlags::EditorContext | EAutomationTestFlags::EngineFilter)
```

两类断言：

1. **结构**：反射统计 `FUNC_BlueprintCallable` 数量，`>= 56`，防止节点被误删
2. **行为**：56 个节点逐个调用，核对"非 Android 默认值"

跑法（不开编辑器）：

```powershell
UnrealEditor-Cmd.exe XRDeviceKitDemo.uproject -ExecCmds="Automation RunTests XRDeviceKit;Quit" `
  -unattended -nop4 -nosplash -nullrhi -log
```

### 2.2 真机冒烟

做成 `UGameInstanceSubsystem`，ini 开关控制：

```ini
[XRDeviceKit]
SmokeTestOnStartup=True
```

开了之后延迟 3 秒（等 Java 侧 `Init` 完成），把全部节点调一遍，每条打一行：

```
SMOKE|GetBatteryLevel=87
SMOKE|GetScreenWidth=2160
SMOKE|GetPackageName=com.YourCompany.XRDeviceKitDemo
```

固定 `SMOKE|` 前缀是为了 `adb logcat | findstr "SMOKE|"` 能一把抓。

### 2.3 APK 检查脚本

```
1. 解包 APK，把所有 classes*.dex 的字节拼起来
2. 搜 3 个 GameActivity 注入方法 + 28 个 XRBridge 符号
3. 检查 Intermediate/Android/ActiveUPL.txt 里有没有我们的 XML
```

全过退出码 0，有缺失退出码 1。

## 3. 写完为什么不是理想效果

### 3.1 契约测试第一次跑就红了，两处

```
Error: Expected '设备 ID 不应该为空' to be false.
Error: Expected '音量档位 >= 0' to be true.
```

我当时写的注释是：

- `GetDeviceId`：设备唯一 ID
- `GetDeviceVolume`：音量档位 0~15

**实测**：Windows 上 `GetDeviceId()` 返回空串，`GetDeviceVolume()` 返回 `-1`。

也就是说，不是代码写错了，是**注释承诺的行为和引擎实际行为不符**。测试在这里起到了"文档校对"的作用。

### 3.2 脚本一跑就语法错误

```
表达式或语句中包含意外的标记“)”。
字符串缺少终止符: '。
```

错误行里还带着乱码 `" 涓?`。

原因：脚本是 UTF-8 **无 BOM**，而 PowerShell 5.1 默认按 ANSI（中文系统是 GBK）解码脚本文件。

### 3.3 命令行完全拿不到输出

`UnrealEditor-Cmd.exe ... | Select-String ...` 输出为空，退出码 255：

```
exit=255
```

但测试其实**跑过了**——只是结果没走 stdout。

---

## 4. 怎么定位的

**3.1**：日志里直接给了断言失败的文件行号，不用猜：

```
LogAutomationController: Error: Expected '设备 ID 不应该为空' to be false.
[C:\...\Tests\XRDeviceKitContractTest.cpp(39)]
```

**3.3**：stdout 空的，但 UE 自己的日志是落盘的。去翻 `Saved/Logs/XRDeviceKitDemo.log`：

```
LogAutomationController: Display: Test Completed. Result={失败} Name={ApiContract} Path={XRDeviceKit.ApiContract}
LogAutomationController: Error: Expected ...
LogAutomationCommandLine: Display: **** TEST COMPLETE. EXIT CODE: -1 ****
```

**结论：自动化测试的输出不在 stdout，在 `Saved/Logs`。**

**3.2**：错误信息里全是乱码，说明是解码问题不是语法问题。查 PowerShell 5.1 的默认编码 → ANSI → UTF-8 无 BOM 的脚本会被当 GBK 解析，中文注释里的引号/括号就被切碎。

---

## 5. 怎么解决的

| 问题 | 改法 |
|---|---|
| 设备 ID 断言 | 删掉非空断言，注释改成"非 Android 平台可能为空" |
| 音量断言 | 放宽成 `>= -1`，注释补"拿不到返回 -1" |
| 脚本编码 | 写成 UTF-8 **带 BOM**（`UTF8Encoding($true)`） |
| 拿不到测试输出 | 一律读 `Saved/Logs/XRDeviceKitDemo.log`，不看 stdout |
