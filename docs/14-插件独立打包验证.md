# 插件独立打包验证

> 日期：2026-11-19
> 目的：确认 `Plugins/XRDeviceKit` 脱离本工程后还能编、还能带走 Android 侧的东西

---

## 1. 这一阶段要做什么

之前所有编译都是在本工程里做的——**插件和工程耦合着编，看不出交付问题**。

这一轮用 `RunUAT BuildPlugin` 把插件单独打成包，再检查包里的内容对不对。

```powershell
RunUAT.bat BuildPlugin `
  -Plugin="...\Plugins\XRDeviceKit\XRDeviceKit.uplugin" `
  -Package="...\Pack\XRDeviceKit" `
  -TargetPlatforms=Win64+Android
```

---

## 2. 怎么做的

BuildPlugin 的流程：把插件拷进一个临时的 `HostProject` → 编译 → 再把编译产物和源码拷到 `-Package` 目录。

所以它能暴露两类问题：

1. **编译问题**：临时工程没有本工程的 unity 组合和 PCH，缺 include 立刻暴露
2. **打包问题**：哪些目录会被带走、哪些被丢掉

---

## 3. 写完为什么不是理想效果

### 3.1 第一次：编译失败，缺头文件

```
XRDeviceKitPlatform.cpp(656): error C2027: 使用了未定义类型 FConfigCacheIni
```

本工程里能过，是因为 unity 编译时别的文件把 `Misc/ConfigCacheIni.h` 带进来了；插件单独编时 unity 组合不同，就露了。

### 3.2 第二次：编过了，但 **JavaLibs 没进包**

包里的顶层只有：

```
Binaries/  Intermediate/  Source/  XRDeviceKit.uplugin
```

`JavaLibs/` 整个目录不见了。查 UAT 日志，最终拷贝只拷了 `Source/` 下的文件：

```
SafeCopyFile ...\HostProject\Plugins\XRDeviceKit\Source\XRDeviceKit\Public\XRDeviceKitLibrary.h
   → ...\Pack\XRDeviceKit\Source\XRDeviceKit\Public\XRDeviceKitLibrary.h
```

**结论：BuildPlugin 只带走 `Source/` 和 `.uplugin`，插件根目录下的自定义目录（JavaLibs）会被丢弃。**

这个不修的话，别人拿到插件包，Android 打包时 `copyDir` 找不到源目录 → 整个 APK 编不过。

### 3.3 Android 没有预编译 .so

`-TargetPlatforms=Win64+Android` 时 Android 确实编了（日志里 `Compile [arm64] ...`），但包里没有 `.so`。

这是**正常的**：源码分发的插件，消费方工程的构建过程会把插件源码一起编进 `libUnreal.so`，不需要预编译产物。只要 `Source/` 在就行。

---

## 4. 怎么定位的

**3.1**：报错直接给了文件和行号，加 include 即可。顺手把 `fopen` 的 C4996 警告也改成 `fopen_s`（Windows 用 `fopen_s`，其他平台用 `fopen`）。

**3.2**：不猜，直接列包里的目录 + 翻 UAT 日志的 `SafeCopyFile` 记录。日志里只有 `Source/...` 的拷贝，没有 `JavaLibs`。

**3.3**：看 Android 的 UBA 日志，确认 `Compile [arm64]` 成功，只是不产出独立 .so。

---

## 5. 怎么解决的

| 问题 | 改法 |
|---|---|
| 缺 `ConfigCacheIni` | `XRDeviceKitPlatform.cpp` 显式 `#include "Misc/ConfigCacheIni.h"` |
| `fopen` 警告 | Windows 走 `fopen_s`，其他平台 `fopen` |
| JavaLibs 丢包 | 在 `Config/FilterPlugin.ini` 里加 `/JavaLibs/...`，让 BuildPlugin 把它一起带走 |

### 先说一个走弯路的方案

第一反应是把 `JavaLibs/` 挪进 `Source/XRDeviceKit/`——`Source` 是 BuildPlugin 必拷的目录，挪进去自然就带上了。

这个方案**能跑通**（APK 和插件包都验证过），但有两个缺点：

1. Java 源码放在 C++ 的 `Source` 目录下，语义上别扭
2. 依赖 BuildPlugin 的内部实现（"Source 必拷"），哪天它改了规则就悄悄失效

所以最后改成用 `FilterPlugin.ini`——这是 BuildPlugin 官方提供的扩展点：

```ini
[FilterPlugin]
; BuildPlugin 只会自动带走 Source/ 和 .uplugin，插件根下的自定义目录必须在这里列出来
/JavaLibs/...
```

改完重新打包，`Pack/XRDeviceKit/` 顶层出现了 `JavaLibs/`，路径和源工程一致，UPL 里的 `$S(PluginDir)/../../../JavaLibs/xrbridge` 也不用改。

### 还没做的

**没在“全新工程”里装一次这个包。** HostProject 只验证了编译，没验证：

1. 把包拷进一个空工程，Android 打包能不能走通
2. `$S(PluginDir)` 在新位置还能不能定位到 JavaLibs

这两条是消费方的真实路径，需要建个空工程跑一遍才敢说“能交付”。

### 附带发现

- 本工程的 `.gitignore` 忽略了 `Pack/`，所以插件包不进版本库——这是对的，包是产物
- BuildPlugin 会连带编译 Shipping 配置，所以插件的 Shipping 分支也顺带验了一次
