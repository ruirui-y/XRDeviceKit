## 4. 中间的一个假失败

第一次跑写操作时：

```
WRITE|volume before=26 after=26      ← 看起来设了没生效
```

查法：在 Java 的 `SetVolume` 里打一行日志，记录目标档位和设置前后的实际档位。

```java
int beforeIndex = am.getStreamVolume(STREAM_MUSIC);
am.setStreamVolume(STREAM_MUSIC, index, 0);
int afterIndex  = am.getStreamVolume(STREAM_MUSIC);
Log.i("XRBridge", "SetVolume percent=50 max=15 target=8 before=7 after=8");
```

结果：**档位确实从 7 变成了 8**，系统层生效了。C++ 侧读回没变，是因为 `FAndroidMisc::GetDeviceVolume()` 读的是引擎缓存的音量状态，广播还没更新。

加了日志之后重跑，读回变成 53（= 8/15 × 100），缓存也跟上了。

**结论：不是接口问题，是"设完立刻读"读到了旧缓存。** 日志留着，以后排查音量问题能直接看档位。
